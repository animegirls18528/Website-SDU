# ระบบจัดเก็บเอกสารอิเล็กทรอนิกส์ (งานระบบกองคลัง - EDMS / Website-SDU)

ระบบเว็บแอปพลิเคชันสำหรับบริหารจัดการ จัดเก็บ ค้นหา ตรวจสอบความถูกต้อง และสแกนเอกสารอิเล็กทรอนิกส์ รองรับการทำงานร่วมกับเครื่องสแกนเอกสาร Canon imageFORMULA DR-G2110 ผ่าน NAPS2 Console CLI พร้อมระบบความปลอดภัยและการประทับ QR Code ตรวจสอบเอกสาร

---

## 🆕 ชุดฟีเจอร์ใหม่ (EDMS v2) — สรุปสำหรับผู้ตรวจรับ

ชุดนี้ต่อยอดจากเวอร์ชันปรับปรุง (ต.ค. 2569) โดยเพิ่มฟีเจอร์ด้านการสแกน การจัดเก็บ ระเบียบงานสารบรรณ และความปลอดภัย
ฐานข้อมูลอัปเกรดอัตโนมัติเป็น schema เวอร์ชัน 5 เมื่อมีการเรียกหน้าเว็บครั้งแรก (**เพิ่มตาราง/คอลัมน์เท่านั้น ไม่ลบหรือเปลี่ยนชื่อของเดิม**) และระบบเดิมยังใช้งานต่อได้

### 1. สแกนทีละปึกด้วยใบปะหน้า (เมนู "สแกนทีละปึก")
1. สร้างเอกสารล่วงหน้าพร้อมพิมพ์ **ใบปะหน้า A4** (QR Code `EDMSCOVER:<รหัส>` + บาร์โค้ด Code128) — `cover_print.php`
2. วางใบปะหน้าไว้หน้าแรกของเอกสารแต่ละชุด แล้วสแกนทั้งปึกครั้งเดียว (หรือเลือกไฟล์ PDF/TIFF ทั้งปึก)
3. เบราว์เซอร์อ่าน QR (jsQR) แยกเอกสารตามใบปะหน้า แสดงตารางตรวจสอบ (จำนวนหน้าไม่ตรงกับที่ควรได้จะเตือน) แล้วแนบเข้าแต่ละรหัสให้
- **สถานีสแกน**: ยิงบาร์โค้ด/พิมพ์รหัส + Enter เพื่อสแกนเข้าเอกสารนั้นทันที พร้อมบันทึกรายการที่ทำแล้วในรอบ
- **โปรไฟล์สแกน** (ตั้งค่า › โปรไฟล์สแกน): ชุดค่า DPI/สี/หน้า/คุณภาพ JPEG ตามประเภทเอกสาร
- **ตรวจคุณภาพภาพ**: เตือนภาพเบลอ มืด เอียง และจำนวนหน้าไม่ตรงที่คาด · **บีบอัด**: แปลงเป็นภาพเทา JPEG เพื่อลดขนาด
- **แทรก/แทนที่/หมุน/ลบหน้า** ในเอกสารที่จัดเก็บแล้ว → สร้างเวอร์ชันใหม่ (ไฟล์เดิมเก็บในแท็บเวอร์ชันเก่า)
- **สแกนจากเครื่องอื่นในสำนักงาน**: โปรแกรมเล็ก `tools/agent/edms-agent.ps1` ส่งไฟล์เข้า "กล่องรับไฟล์" ด้วย token (เมนู ความปลอดภัยบัญชี › Token เครื่องสแกน; เก็บเป็นแฮช SHA-256)

### 2. ความสมบูรณ์ของไฟล์และการสำรองข้อมูล (ตั้งค่า › พื้นที่และสำรองข้อมูล)
- ตรวจ SHA-256 ของทุกไฟล์เทียบกับค่าที่บันทึกไว้ (`tools/integrity_check.php` ตั้งเวลารายเดือนได้ หรือกดตรวจเอง)
- สำรองข้อมูลไปไดรฟ์ภายนอก/NAS เพิ่มจากที่เก็บหลัก พร้อมตรวจ hash ของชุดที่คัดลอก
- ปุ่ม **ทดลองกู้คืน** (`tools/restore_test.php`): นำชุดสำรองล่าสุดเข้าฐานข้อมูลชั่วคราวและตรวจไฟล์ ไม่กระทบข้อมูลจริง

### 3. ที่เก็บต้นฉบับกระดาษและทะเบียนยืม-คืน
- ห้อง/ตู้/ชั้น/กล่อง ต่อเอกสาร · ทะเบียนยืม-คืน (ผู้ยืม วันกำหนดคืน) แจ้งเตือนเมื่อเกินกำหนด · ค้นหาตามที่เก็บและสถานะการยืมได้

### 4. การค้นหาและจัดการเอกสาร
- ค้นหาขั้นสูง (ช่วงจำนวนเงิน ปีงบประมาณ หน่วยงาน ช่องดัชนี ที่เก็บ สถานะยืม ข้อมูลส่วนบุคคล) + บันทึกเงื่อนไขไว้ใช้ซ้ำ
- แจ้งเตือนไฟล์ซ้ำตอนอัปโหลด (เทียบ SHA-256 ของไฟล์ต้นฉบับ) · เชื่อมโยงเอกสารที่เกี่ยวข้อง
- จัดการทีละหลายฉบับ: ย้ายแฟ้ม เพิ่มแท็ก ส่งตรวจ อนุมัติ ตั้งที่เก็บ ใบปะหน้า ลิงก์ผู้ตรวจ ถังขยะ/กู้คืน
- **กระดิ่งแจ้งเตือนในระบบ** (แทนการแจ้งเตือนทาง LINE ที่นำออกแล้ว)

### 5. ลิงก์สำหรับผู้ตรวจสอบภายนอก (เช่น สตง.) — `share.php`
- ผู้ดูแลเลือกเอกสาร กำหนดผู้รับและวันหมดอายุ (ไม่เกิน 180 วัน) ได้ลิงก์ที่เปิดดูได้โดยไม่ต้องมีบัญชี เห็นเฉพาะเอกสารที่เลือก
- ทุกไฟล์มีลายน้ำ "REVIEW COPY" ระบบนับและบันทึกทุกครั้งที่เปิด ยกเลิกลิงก์ได้ทันที (ตั้งค่า › ลิงก์ผู้ตรวจ) · หมดอายุ/ถูกยกเลิก → HTTP 410
- ⚠️ เอกสารที่ติดป้าย PDPA จะถูกแชร์ได้เมื่อผู้ดูแลเลือกเอง โปรดตรวจก่อนสร้างลิงก์

### 6. ระเบียบงานสารบรรณ — การทำลายเอกสาร (เมนู "ทำลายเอกสาร")
- สร้าง **บัญชีหนังสือขอทำลาย** จากเอกสารครบอายุ/คำขอทำลาย → แต่งตั้งคณะกรรมการ (อย่างน้อย 3 คน) → พิจารณา (ทำลาย/ขยายเวลาเก็บ) → อนุมัติ → ดำเนินการ
- พิมพ์บัญชีขอทำลาย (`destruction_print.php?id=`) และรายงานประจำปี (`?year=`) · ทุกขั้นบันทึก audit log

### 7. รายงานผู้บริหาร (เมนู "รายงาน")
- เอกสารตามปีงบประมาณและประเภท · ผลงานสแกนรายบุคคล · พื้นที่ดิสก์และคาดการณ์วันเต็ม · รายงาน PDPA ว่าใครเข้าดูข้อมูลส่วนบุคคล · ส่งออก CSV

### 8. ความปลอดภัยและ PDPA
- **ลายน้ำ** ตอนดาวน์โหลด/ทุกครั้งที่เปิด (ตั้งได้) · กำหนดว่าบทบาทใดดาวน์โหลดได้ (ที่เหลือดูอย่างเดียว) (ตั้งค่า › นโยบาย PDPA และความปลอดภัย)
- **ตรวจจับข้อมูลส่วนบุคคลอัตโนมัติ** (เลขบัตรประชาชน 13 หลักที่ checksum ถูกต้อง, เลขบัญชี) → ป้าย PDPA · ผู้ไม่มีสิทธิ์เห็นเลขถูกปิดบังในรายการ/ข้อความค้นหา/ดัชนี/**ไฟล์ CSV** และเปิดไฟล์นั้นไม่ได้ (ภาพสแกนปิดบังเลขไม่ได้ จึงใช้การปิดกั้นแทน) · ผู้ดูแลติด/ยกเลิกป้ายเองได้
- **ลายมือชื่อดิจิทัล PDF** (เปิดใช้ในนโยบาย): TCPDF + ใบรับรองที่ระบบสร้างเอง หรือติดตั้งไฟล์ .p12 ของหน่วยงาน
- **ยืนยันตัวตนสองขั้น (TOTP)** ใช้กับ Google/Microsoft Authenticator + รหัสกู้คืน 10 ชุด · บังคับกับผู้ดูแลระบบได้ · ผู้ดูแลรีเซ็ตให้ผู้ใช้ได้
- **อุปกรณ์ที่เข้าสู่ระบบอยู่**: ดูรายการ สั่งออกจากระบบรายเครื่อง/ทุกเครื่องอื่น (session เก็บในฐานข้อมูล)
- ลืมรหัสผ่านผู้ดูแลระบบ: `php tools/reset_password.php <ชื่อผู้ใช้>` (รันในเครื่องเซิร์ฟเวอร์เท่านั้น)

### ข้อจำกัดที่ควรรู้
- ไม่มี JBIG2 (ทำในเว็บไม่ได้) การบีบอัดใช้ภาพเทา JPEG แทน · ลายมือชื่อที่ระบบสร้างเองยังไม่เป็นที่เชื่อถือใน Adobe Reader และยังไม่มี timestamp จากผู้ให้บริการภายนอก (TSA)
- PDF ที่ใช้ compressed xref/object stream ต้องผ่านการแปลงในเบราว์เซอร์ (ทำอัตโนมัติตอนอัปโหลด) จึงจะประทับ QR/ลายน้ำ/ลายมือชื่อได้ — ไฟล์ที่นำเข้าผ่าน API ตรงโดยไม่ผ่านขั้นตอนนี้ระบบจะเก็บฉบับเดิมและแจ้งเตือน
- หน้าเว็บโหลดไลบรารี (pdf.js, pdf-lib, Chart.js, JsBarcode, jsQR) จาก CDN จึงต้องมีอินเทอร์เน็ต หากใช้ในเครือข่ายปิดต้องดาวน์โหลดไลบรารีมาไว้ในเครื่อง
- การสั่งสแกนเนอร์จริงต้องติดตั้ง NAPS2 (ยังไม่ได้ทดสอบกับเครื่อง Canon จริงในชุดนี้)
- การอัปเกรดฐานข้อมูลเดิมใช้ `ADD COLUMN IF NOT EXISTS` ซึ่งเป็นไวยากรณ์ MariaDB (XAMPP ใช้ได้) · ฐานข้อมูลใหม่ติดตั้งจาก `config/schema.sql` อัตโนมัติ

### การตั้งค่าเฉพาะเครื่อง (`config/local.php`)
คัดลอก `config/local.example.php` เป็น `config/local.php` (ไฟล์นี้ไม่ขึ้น git และเข้าผ่านเว็บไม่ได้) เพื่อกำหนดชื่อฐานข้อมูล/รหัสผ่าน, `BACKUP_DIR`, `SIGN_KEY_DIR` (โฟลเดอร์กุญแจลายมือชื่อ ต้องอยู่นอก htdocs) ฯลฯ

## 🛠️ รายละเอียดสถาปัตยกรรมและไฟล์สำคัญ

### 1. หน้าเว็บหลัก (User Interface & Frontend)
- **[index.php](file:///c:/xampp/htdocs/Website-SDU/index.php)**: 
  - ส่วนติดต่อผู้ใช้งานหลักแบบ SPA (Single Page Application)
  - มีระบบ Dashboard แสดงสถิติและกราฟ (Chart.js)
  - จัดการเอกสาร (เพิ่ม, แก้ไข, ลบ, ค้นหา, ดูตัวอย่าง PDF ด้วย PDF.js)
  - รองรับการสแกนเอกสารโดยตรงจากเครื่องสแกนเนอร์ผ่านเบราว์เซอร์
  - เมนูตั้งค่าระบบและจัดการผู้ใช้งาน (เฉพาะสิทธิ์ Admin)
- **[login.php](file:///c:/xampp/htdocs/Website-SDU/login.php)**: หน้าฟอร์มเข้าสู่ระบบ ป้องกัน Brute-force Login และ Session Fixation
- **[setup.php](file:///c:/xampp/htdocs/Website-SDU/setup.php)**: ใช้งานได้เฉพาะเมื่อยังไม่มีผู้ใช้ในระบบ เพื่อกำหนดรหัสผ่านบัญชี Admin คนแรก
- **[verify.php](file:///c:/xampp/htdocs/Website-SDU/verify.php)**: หน้าสาธารณะสำหรับตรวจสอบข้อมูลเอกสาร เมื่อผู้ใช้งานใช้มือถือสแกน QR Code ที่ถูกประทับไว้บนไฟล์ PDF

### 2. โมดูล API (`/api`)

- **[api/dashboard_stats.php](file:///c:/xampp/htdocs/Website-SDU/api/dashboard_stats.php)**: คำนวณยอดเอกสารรายสัปดาห์, อัตราส่วนแฟ้ม, Active Users และดึง Audit Logs

### 3. โครงสร้างฐานข้อมูล (`database.sql`)
ฐานข้อมูลชื่อ `dms_system` ประกอบด้วยตารางสำคัญ:
- `documents`: ข้อมูลเอกสารหลัก (รหัสเอกสาร, ชื่อเอกสาร, แฟ้ม, วันที่, พาธไฟล์, CustomData รูปแบบ JSON)
- `folders`: โครงสร้างแฟ้มจัดเก็บเอกสาร
- `prefixes`: คำนำหน้าเลขเอกสารสำหรับสร้างรหัสอัตโนมัติ (เช่น DOC, INV)
- `custom_fields`: ฟิลด์ข้อมูลเพิ่มเติมที่กำหนดเองแบบ Dynamic
- `users`: ข้อมูลผู้ใช้งาน, แฮชรหัสผ่าน (bcrypt), สิทธิ์ (`admin`, `staff`), ประวัติล็อกอินล้มเหลว
- `audit_logs`: บันทึกกิจกรรมของระบบ (การอัปโหลด, ลบ, แก้ไข, การตั้งค่า, พร้อม IP Address)
- `system_settings`: การตั้งค่าระบบ เช่น URL สาธารณะ อายุการเก็บเริ่มต้น

### 4. การตั้งค่าระบบสแกนเอกสาร (Scanner Setup)

## 🔒 ฟีเจอร์ความปลอดภัย (Security Features)

- **CSRF Protection**: มีการตรวจสอบ CSRF Token ทุกคำขอประเภท POST / State-changing
- **Brute-Force Protection**: ล็อกบัญชีชั่วคราวเมื่อล็อกอินผิดติดต่อกันเกินจำนวนครั้งที่กำหนด
- **Secured File Access**: โฟลเดอร์ `uploads/` ถูกปิดกั้นการเข้าถึงจาก URL ตรง การเข้าถึงไฟล์ทุกไฟล์ต้องผ่าน `api/file.php` ซึ่งตรวจสอบสิทธิ์ Session ก่อนเสมอ
- **Audit Logs**: มีระบบบันทึกประวัติการกระทำสำคัญทุกขั้นตอนพร้อม IP Address ของผู้ใช้งาน
- **QR Code Verification**: ประทับ QR Code อัตโนมัติลงในหน้าเอกสาร PDF ทุกหน้า เพื่อให้บุคคลภายนอกสแกนตรวจสอบความถูกต้องผ่าน `verify.php` ได้ทันที

## ✨ ฟีเจอร์ที่เพิ่มในเวอร์ชันปรับปรุง (ต.ค. 2569)

### การค้นหาและคลังเอกสาร
- ค้นหาฝั่งเซิร์ฟเวอร์ แบ่งหน้า ค้นได้ทุกเอกสาร (เดิมค้นได้เฉพาะ 1,000 ฉบับล่าสุด) จากรหัส ชื่อเรื่อง แท็ก ดัชนีเพิ่มเติม และข้อความในไฟล์ PDF
- ตาราง `document_search` เก็บข้อความค้นหาที่ปรับรูปแบบแล้ว (ตัวพิมพ์เล็ก, รวม "ํา" เป็น "ำ") จึงค้นครั้งเดียวต่อคำค้น
- ตัวกรอง: แฟ้ม ช่วงวันที่ ใกล้ครบอายุ ครบอายุแล้ว รอตรวจสอบ ฉบับร่าง ขอทำลาย ยังไม่มีไฟล์ ถังขยะ · ส่งออก CSV ตามตัวกรองปัจจุบัน
- หน้ารายละเอียดเอกสาร: ข้อมูลดัชนี ไฟล์ปัจจุบัน เวอร์ชันเก่า และประวัติการใช้งานรายเอกสาร

### การจัดเก็บไฟล์
- ไฟล์อยู่ใน `uploads/ปี/เดือน/` · ตาราง `document_files` เก็บ SHA-256 จำนวนหน้า ผู้อัปโหลด และเวอร์ชัน
- เก็บไฟล์ต้นฉบับ (`*_orig.pdf`) แยกจากฉบับที่ประทับ QR · แทนที่ไฟล์แล้วฉบับเดิมยังอยู่ในประวัติเวอร์ชัน
- ลบเอกสาร = ย้ายไปถังขยะ (กู้คืนได้) ลบถาวรอัตโนมัติเมื่อครบจำนวนวันที่ตั้งไว้ (ค่าเริ่มต้น 30 วัน)
- เลขเอกสารจองแบบ atomic (`doc_sequences`) ถ้ามีผู้อื่นใช้เลขไปก่อน ระบบออกเลขถัดไปให้
- หน้าจัดหน้าเอกสาร: หมุน ลบ เรียงหน้า และรวมหลายไฟล์ (รวมรูปภาพ) เป็น PDF เดียว ทำในเบราว์เซอร์ด้วย pdf-lib

### QR Code และการตรวจสอบ
- QR ใช้ token สุ่ม (`verify.php?t=...`) เดาไม่ได้ · QR รุ่นเก่า (`?id=`) ยังใช้ได้แต่แสดงข้อมูลน้อยลง
- ผู้ถือไฟล์อัปโหลดไฟล์ในหน้าตรวจสอบเพื่อเทียบ SHA-256 กับต้นฉบับได้ (ตรวจจับไฟล์ที่ถูกแก้ไข)
- แก้บั๊กเดิม: การประทับ QR ทำให้มีหน้าว่างแทรกหลังทุกหน้า
- PDF จากโปรแกรมสมัยใหม่ (compressed xref) ถูกบันทึกใหม่ในเบราว์เซอร์ก่อนอัปโหลด เพื่อให้ประทับ QR ได้

### การสแกน
- คิวสแกนทำงานเบื้องหลัง (`tools/scan_worker.php`) หน้าเว็บไม่ค้าง สแกนได้ทีละงาน งานอื่นรอคิว ยกเลิกงานที่รอคิวได้
- ตัวเลือกใหม่: ปรับภาพเอียง, ข้ามหน้าว่าง, OCR ภาษาไทย/อังกฤษ, แยกเอกสารด้วยแผ่นคั่น Patch-T, บันทึกเป็น PDF/A-2b, เลือกเครื่องสแกน (TWAIN / WIA / eSCL เครือข่าย)
- แก้บั๊กเดิม: ไฟล์ที่สแกนเปิดดูไม่ได้ (`file.php` รับเฉพาะชื่อ `doc_`) และหน้าเว็บแสดงคำสั่งระบบเมื่อสแกนผิดพลาด

### สิทธิ์ ขั้นตอนงาน และวงจรชีวิตเอกสาร
- บทบาทใหม่ "ผู้ดูเอกสาร" (viewer) ดูและค้นหาได้อย่างเดียว · จำกัดแฟ้มที่ผู้ใช้แต่ละคนเข้าถึงได้
- บันทึก audit log ตอนเปิดดูและดาวน์โหลดไฟล์
- ขั้นตอน: ฉบับร่าง → รอตรวจสอบ → อนุมัติ (ผู้ดูแลระบบอนุมัติหรือตีกลับ)
- อายุการเก็บกำหนดตามประเภทเอกสาร (prefix) ได้ · ขออนุมัติทำลายเอกสารที่ครบอายุ → ผู้ดูแลอนุมัติ → ถังขยะ

### ดูแลระบบ
- หน้า "พื้นที่และสำรองข้อมูล": ขนาดไฟล์ พื้นที่ดิสก์ ไฟล์ขยะที่ไม่ได้ผูกกับเอกสาร สั่งอ่านข้อความในไฟล์ทั้งหมด
- สำรองข้อมูล (`tools/backup.php`): ฐานข้อมูล (gzip) และไฟล์ทั้งหมด ไปที่ `BACKUP_DIR` นอก htdocs เก็บ 14 ชุดล่าสุด
